1. 第一次使用：最短路径

  1. 拿到完整的 Windows 便携 ZIP 和对应 SHA256。只有源码、单个 HTML 或旧内部候选不算完整交付。
  2. 全部解压至本地、可写、短路径，建议整个 workbench 路径不超过 80 个字符，例如 D:\Apps\workbench；没有 D 盘就选自己的短目录。
  3. 双击 start-workbench.cmd，后台自动启动并打开网页。首次可能短暂闪出命令窗口。
  4. 阅读页面展示的随包条款，自行决定是否同意；不同意可以退出，不执行后续检测或下载。
  5. 按官方文档自己安装、登录 Claude Code。工作台不随包提供 Claude、账号、密钥和额度。
  6. 网页点击“确认并准备测试浏览器”，阅读提示并确认，才会从官方源下载约 173 MiB。完成后点“重新检测（不调用模型）”。
  7. 状态允许后，按“需求 → 设计 → 下载修改 → 上传 → 拆分审核 → 手动开始 → 测试 → 人工验收”操作。
  8. 结束时等所有项目停稳，点网页“退出工作台”。关闭标签不等于退出后台。

日常使用：只需双击同一个 CMD。无需每次打开终端，无需每次重新安装或下载。重复双击只重开已有实例，不应为重开网页而结束进程。

2. 电脑、账号与网络要求

项目要求与实际边界
系统首版面向 Windows x64，本机验证环境为 Windows 11 Pro 10.0.26200。Windows 10／11 干净系统尚未验收；ARM64、macOS、Linux 和网络共享目录不在本版支持范围。
运行时完整包自带 Python 3.14.3、Node 24.14.0、Playwright/core 1.58.2、reason-network 0.10.8；不要求使用者另装这些运行时，不需要 npm install 或构建。
浏览器用自己的常用浏览器打开工作台；自动化测试另需固定 Chrome for Testing 145.0.7632.6（revision 1208），由首次明确确认后下载，不安装到系统。
Claude每个人自己安装并登录原生 Claude Code。当前本机 CLI 为 2.1.307；兼容性按所需命令参数检测，不是仅按版本号承诺所有新旧版本可用。
账号与费用使用自己的订阅、Console 或已有提供商配置。工作台不提供免费模型额度，不代选套餐，不收集或复制密钥。
网络需要访问官方浏览器下载源和自己配置的模型服务。工作台本身监听 127.0.0.1，不是云端多人服务；本地运行不等于模型离线。
存储预留完整包、约181MB浏览器下载、解压临时副本与项目空间；建议至少留 2GB 可用空间，这是使用建议，不是运行中磁盘保证。项目及证据会继续增长。
适用任务本服务新建的受管理项目、无需依赖安装或构建的静态 HTML/CSS/JS。不能把任意现有业务仓库、后端部署或复杂构建任务直接交给本版。

3. 下载、校验与完整解压

  1. 只使用可信发送者提供的干净 ZIP；同时核对发送者另行给出的 SHA256。同目录校验文件能发现损坏，但不能独立证明发送者身份。
  2. 可选：在 PowerShell 中核对，替换为实际 ZIP 的完整路径：
    Get-FileHash -Algorithm SHA256 -LiteralPath 'D:\Downloads\relay-workbench-win-x64.zip'
    把显示的完整 64 位摘要与发送者提供的值逐字比较；不同就停止使用，不修改清单凑匹配。
  3. 右键 ZIP → “全部解压”。确保不是运行压缩包预览里的 CMD。不要将目录反复套成 workbench\workbench\workbench。
  4. 选择自己有写入权限的短目录。中文和空格可以使用，不要放在 Program Files、网络盘、同步盘、临时解压目录或过深路径。不需要管理员身份。
  5. 解压后至少应看到：
    workbench/
  start-workbench.cmd    日常启动入口
  START-HERE.txt        快速说明
  USER-GUIDE.html       本手册；双击可离线阅读
  portable.json         固定文件摘要与依赖路径
  DEPENDENCIES.json     随包组件版本与来源
  DISTRIBUTION-TERMS.txt
  index.html / *.js / styles.css
  p1/                   本机后台
  vendor/               包内运行时
  licenses/             已保留的通知
  PREVIEW-STATUS.txt    预览版范围（交付包附带）

第一次启动后才出现 userdata/。干净 ZIP 不应含任何人的项目、登录、同意记录或运行证据。不要修改、删除 portable.json 或 vendor/ 中的文件；校验失败不会偷偷改用发送者电脑的全局工具。

Windows 深路径可能导致浏览器资源解压失败。本机已复现同一已核验归档在269字符目标路径失败、短目录成功；当前会在部分写入前明确拒绝过长目标并指导移到短目录，不会修改注册表或开启系统长路径。2026-10-23本机新短目录的生产官方下载、完整大小与SHA256、安全解压、真实浏览器自检及receipt检查已通过（317.409秒、单次尝试）；这不是任意网络或干净Windows保证，历史TLS失败仍保留。

4. 自己安装并登录 Claude Code

  1. 打开 Claude Code 官方安装说明，选择 Windows／原生安装。按官方当前步骤准备所需 Git for Windows；其官网为 git-scm.com。不要从聊天或不明网盘复制安装脚本。
  2. 由你在自己的终端完成安装。工作台不会自动运行远程安装脚本、全局安装、更新客户端或修改认证配置。官方文档可能变更，本手册不固定一条未经本轮在线核实的远程安装命令。
  3. 安装后重新打开终端，先检查：
    claude --version
    若找不到命令，按官方文档核对安装和当前终端环境。不要向工作台填任意 exe 路径。
  4. 用自己的账号登录：
    claude auth login
    按 CLI 和浏览器的官方提示完成。已有自定义提供商配置的，按该配置原有接入方式操作，不为了工作台强行覆盖它。
  5. 回工作台点击“重新检测（不调用模型）”。首次安装／登录可用终端；以后正常使用不要求一直开着终端。

如果正在这次 Claude Code 对话里操作：需要自己运行交互登录时，可在提示框输入 ! claude auth login，它会在当前会话执行；也可以使用自己的终端。普通接收者不需要安装这个聊天会话。

不要在工作台、需求、任务驳回理由、截图或求助日志中粘贴 API key、登录 token、密码、认证环境变量值。工作台不共享发送者的账号，也不会把发送者的登录打进 ZIP。

5. 双击启动与首次准备

5.1 正常启动

双击 start-workbench.cmd。自动打开的是动态本机地址 http://127.0.0.1:某端口/，不用记端口，也不用手动输入登录 URL。启动器可能短暂闪出窗口，然后后台由包内 Python 承载；不是安装常驻系统服务。

不要把 index.html 当真实入口：直接打开它是明确标注的历史模拟，不调用 AI。页面出现“模拟”“本地静态页面”时，请改用 CMD。HTTP 连接失败不会降级成模拟。

5.2 两次独立确认

  1. 随包组件条件：先阅读页面完整正文，自己决定是否点击“我已阅读并同意当前发行条款”。不同意可以退出。确认绑定正文摘要，正文变化需重确认；不因此自动下载、检测或调用模型。
  2. 测试浏览器：点“确认并准备测试浏览器”，在提示中明确确认。固定源为 cdn.playwright.dev，允许官方 storage.googleapis.com 重定向。显示实际字节，完成大小与 SHA256 校验、安全解压及本地浏览器自检后才就绪。

固定下载约 173 MiB（181196793字节）。慢网络可能需要几分钟；显示的是实际状态，不承诺固定结束时间。失败不自动重试，刷新不重新下载。处理原因后再次明确确认才会重试；失败的临时文件不作为可用浏览器安装，已有未知目录不被覆盖。准备期间不能退出或移动文件夹。

5.3 看懂“重新检测”

显示项你该做什么
客户端缺失按第4节安装自己电脑的原生 Claude Code，再重检。
版本／参数不兼容参考官方说明由自己更新客户端；工作台不自动更新。
明确未登录自己登录，再重检；不会允许模型任务入队。
登录未知未知不等于已登录。确认自己已有配置确实可用、且必需参数与本地依赖通过后，可自行选择“使用已有本机配置继续（接入未验证）”；它不运行模型，下一次重检会撤销该确认。
依赖自检失败先确认浏览器准备完成、包完整、路径短且可写，按故障表处理。
本地自检通过只说明固定本地检测通过，不证明模型网络、额度、真实流式协议或完整闭环。

检测固定执行 Claude version／help／auth status，另做本机依赖与真实 Chromium 检查，不调用模型。刷新只读取缓存，不自动重检；不要把检测绿灯理解为“之后不会收费或不会失败”。

6. 完整工作流程与小例子

需求 → 生成设计 → 下载修改 → 上传确认 → 按上传版拆分 → 逐项审核 → 手动开始 → 开发 → 独立测试 → 显式返修／复测 → 人工验收

6.1 推荐的第一次试用需求

做一个不需要构建和外部依赖的静态待办清单网页。
文件限 index.html、styles.css、app.js。
支持新增、完成、删除、按未完成筛选；空内容不能新增。
在普通独立浏览器中刷新后保留数据；375px宽度不横向溢出。
不接外部API、不需要登录、不安装任何包。
请写清各功能的可操作验收步骤。

这只是供你填写的示例，不是预生成交付物；真实点击生成会调用你自己的模型，可能计费。

6.2 设计文档不是自动批准

  1. 在工作台新建独立项目，填自己的需求，使用三个 Claude 岗位。只支持本服务创建的项目，不填现有业务目录。
  2. 点“生成设计文档（真实 Claude）”。这是架构岗位的实际模型调用，生成完仍不能直接开工。
  3. 下载设计文档，用编辑器逐项检查范围、文件、约束、验收操作。修改后另存严格 UTF-8 的 .md 或 .txt，不超过256KiB。
  4. 上传确认版，核对正文、U版本与 SHA256。只有上传的版本作为拆分依据；旧生成／下载动作不等于人工批准。
  5. 点“按上传版本拆分（真实 Claude）”。改变需求或重新上传会使旧批准失效，不能沿用旧版本直接执行。

6.3 逐项通过或驳回

逐个看职责、说明、验收点和依赖。合理就点“通过此任务”；不合理写具体原因后驳回，再点“仅重做此任务”。例如：

驳回原因：验收只写“功能正常”，没有验证空输入和刷新持久化。
请补充可执行步骤；不要改动无关任务的范围。

只重做被驳回项，无关任务内容、版本和批准保留；受影响的下游会要求显式重审。全部通过只解锁开始按钮，不自动开工。最后由你手动开始真实开发。

6.4 开发、测试与最终验收

  1. 开发岗位、测试岗位是独立原生 Claude CLI，按阶段串行交接；reason-network 保留 TASK → 模型显式 ACK → RESULT。不是本聊天子 Agent 冒充岗位。
  2. 测试使用独立检查与宿主可信复跑。首次实际浏览器检查返回测试员前冻结测试文件；开发者不能改测试期望凑通过。
  3. 失败后需要你明确发起返修，最多两轮，再按冻结规格复测。协议失败的显式重试与返修不是同一个按钮。
  4. 到“实际测试通过，待人工验收”，查看产物、实际证据与所有需求。自动检查通过不代表所有自然语言验收点已覆盖，也不代表视觉质量已由人确认。
  5. 只有你自己确认，才记录人工验收。需要时可显式重新独立测试，会再次调用测试岗位。

真实模式没有“手点开发完成／测试通过”的捷径。ACK只证明该阶段的协议回执，RESULT或exit0也不能代替实际证据。生成的预制演示和真实项目必须区分。

7. 怎样看真实输出和状态

切到“Claude 实时输出”标签，看当前岗位、attempt、实际 PID，以及排队／准备与 CLI 运行分别计时。

  • 只显示真实公开 assistant 文本和宿主实际工具起止，不显示思维链、system/user消息、工具参数、原始结果或stderr。
  • “超时剩余”依据实际进程等待 deadline，不是预计完成时间；不会编造百分比。
  • 模型可能只调用工具，设计正文可能只经结果工具提交。此时“暂无公开文本”不等于没有工作，不会伪造撰写步骤。
  • 30秒无可展示事件只提示静默；页面心跳不是模型活动，也不自动判失败。
  • CLI退出后运行时长冻结，宿主可能继续校验。最终是否成功只看权威状态，不看最后一行自称“完成”。
  • 向上滚动会暂停跟随；点“跟随最新”恢复。只保留有界尾部，不是完整逐字录像。
  • 旧方式启动的任务不会因刷新升级成流式，不为日志重启当前任务。新版功能只对以后安全启动的实例和新任务生效。

8. 费用、暂停、终止与重试

操作是否调用模型／效果
打开、刷新、重开网页、看手册不调用模型；关闭标签不停止后台。
重新检测／准备浏览器不调用模型；检测可能涉及CLI登录状态网络，下载会访问固定官方源。
生成设计、拆分、局部重做、开始开发、测试、返修、显式重试会使用使用者自己的模型配置，可能计费。失败不会自动重试计费。
暂停调度当前原子阶段继续，结束后不派下一项；不是冻结正在运行的CLI。暂停状态不能直接退出后台。
终止本轮撤销批准并请求停止进程树、排空宿主工具；停止未证明前不放行，不显示已安全停稳。
显式重试失败阶段仅在输入与批准未变且已安全停止时可用；每失败阶段最多2次，不适用于未知旧租约强行恢复。
退出工作台检查所有项目及执行器，存在排队、活动、暂停、停止中、未知租约或恢复待核验会拒绝；不代你终止模型。

默认单阶段20分钟、整轮120分钟、最多2轮返修，不代表费用封顶。费用只显示CLI实际报告的值；没有则未知，不是实际账单承诺。账号收费请以自己的服务商记录为准。

9. 产物、数据、备份与迁移

默认数据在解压目录下 userdata/。启动器选择同包数据根，不偷偷迁到开发者电脑路径。

userdata/
  workbench.sqlite3          项目权威状态（可能另有SQLite辅助文件）
  projects/<项目ID>/
    product/                 真实生成的HTML/CSS/JS产物
    tests/                   测试规格
  evidence/                  本地执行证据和原始审计
  browser/chromium-1208/      本地准备的测试浏览器及receipt
  distribution-consent.json 当前正文的本机同意记录（确认后才有）

另有遥测和启动诊断文件；不要把示例列表当成全部可安全公开的文件。查看生成产品可先用页面的预览／产物入口。需要带走静态站点时，在该项目完全停稳后复制其完整 product/ 到另一个新目录；这是交付自己生成的网站，不是重新分发工作台。

隔离预览可能不能使用localStorage，收藏或持久化应在普通独立浏览器环境另行核验，不能把受限预览行为当作完整浏览器测试。

备份与同一使用者移动

  1. 确认所有项目停稳，通过网页“退出工作台”，不要在后台仍写SQLite时直接压缩。
  2. 备份整个工作台和完整 userdata/，放到自己受控的私密位置；保留版本对应，不要只拷贝单个SQLite文件遗漏辅助数据。
  3. 同一使用者同一电脑改短路径：正常退出后移动整个目录，再双击新位置入口。不要旧目录和新目录同时开两份处理同一数据。
  4. 跨电脑恢复、跨版本自动升级和异常租约恢复尚未验收。不要把“可拷贝文件”解释成“运行状态可安全热迁移”。先保留原备份，不覆盖新旧数据根。

本地原始审计可能含需求、源码和工具正文。公开输出做脱敏不等于整个userdata无敏感数据。不要把运行目录压缩给别人或公开上传 evidence。Claude认证由各人原配置管理，不在包里迁移。

11. 交给其他人、更新与卸载

交给新使用者

  1. 发送原始干净ZIP、对应SHA256和本手册，不要从自己的userdata运行目录重新压缩。
  2. 告知接收者：需要自己的Claude Code和账号；浏览器首次确认下载；这是功能预览，有未验项，不承诺所有电脑开箱即用。
  3. 接收者完整解压到短路径，自己阅读条款、安装登录、下载和检测；发送者不能预先代同意或复制账号。
  4. 先按第12节用非敏感小项目检查，再决定是否承担真实模型费用。

更新

无自动更新。先正常退出并备份旧版本；新版解压到新空目录，不覆盖旧vendor、portable.json和userdata，不把新旧文件混合。跨版本数据迁移未验收，先保留旧版独立可回退的备份。更新后旧attempt不会变成实时流式任务。

卸载

先在页面正常退出，再按需私密备份产物和userdata。确认不再需要后，可自行删除这份解压目录；工作台不安装系统服务／自启，不修改全局PATH或MCP。你另行安装的Claude Code／Git及其账号配置不随工作台删除，也不应由工作台清理。

既有第三方通知保留，本轮按需求不开展许可证完整性审阅；此手册和功能ZIP不提供法律再分发批准。不要把“技术上可拷贝”写成“法律义务已审核通过”。
